# GitHub Pages에서 사용하기

이 앱은 HTML, 인라인 CSS와 브라우저 네이티브 ES 모듈을 그대로 게시합니다. 서버, 외부 API, 새 런타임 의존성이나 번들 생성 과정이 필요하지 않습니다. 아래 내용은 게시 담당자를 위한 절차이며, 이 변경안 자체는 저장소 설정을 변경하거나 실제 배포를 수행하지 않습니다.

## 게시 담당자 절차

1. 구현이 반영된 브랜치에 루트 `index.html`과 `src/web.js`, `src/recommendation.js`, `src/classics.js`가 함께 있는지 확인합니다.
2. 게시 전 `npm test`와 `npm run build`가 성공하는지 확인합니다. 빌드는 JavaScript 문법 검사이며 별도의 출력 디렉터리를 생성하지 않습니다.
3. GitHub 저장소의 **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**로 선택합니다.
4. 구현이 반영된 브랜치와 **/(root)** 폴더를 선택하고 저장합니다. 기존 workflow 파일을 수정할 필요는 없습니다.
5. 게시가 완료되면 Pages 설정에 표시된 사이트 주소를 엽니다. 기본 프로젝트 주소는 `https://erpsarang.github.io/classic-paragraph-wit/`입니다. 실제 접속 주소는 Pages 설정의 안내를 기준으로 합니다.

`index.html`은 `./src/web.js`를, 각 모듈은 같은 디렉터리의 모듈을 상대 URL로 가져옵니다. 따라서 프로젝트 하위 경로에서도 자원을 불러올 수 있습니다. `index.html`과 `src` 디렉터리의 상대 위치를 유지해야 합니다.

## 스마트폰 사용자

스마트폰 브라우저에서 게시된 주소를 열면 작품명, 저자, 원문 한 문단과 한국어 위트가 바로 표시됩니다. **다른 고전 추천**을 누르면 직전에 본 작품을 제외한 추천이 표시됩니다. 별도의 설치, 개발환경, 터미널은 필요하지 않습니다. JavaScript가 활성화되어 있어야 합니다.

## 배포 후 모바일 검증

- 스마트폰의 Safari 또는 Chrome에서 게시된 주소를 직접 열고 새로고침해 최초 추천의 네 항목이 모두 표시되는지 확인합니다.
- **다른 고전 추천**을 여러 번 눌러 매번 직전 작품과 달라지고 저자, 문단, 위트도 함께 갱신되는지 확인합니다.
- 좁은 화면과 가로 방향, 글자 확대 상태에서 긴 문단이 줄바꿈되고 가로 스크롤 없이 읽히는지 확인합니다.
- 버튼이 충분히 크고 쉽게 눌리는지 확인합니다. 키보드 사용 시 Tab으로 버튼에 접근하고 포커스 표시, Enter 및 Space 동작을 확인합니다.
- VoiceOver 또는 TalkBack으로 작품과 각 항목을 읽고 추천 변경이 안내되는지 확인합니다. 갱신 후에도 버튼을 계속 조작할 수 있어야 합니다.
- 화면이 준비 문구에 머물거나 버튼이 활성화되지 않으면 JavaScript 설정과 게시된 `src` 모듈의 접근 가능 여부를 확인합니다.

자동 테스트는 추천 선택, DOM 갱신 및 정적 연결을 검사합니다. 실제 브라우저의 레이아웃과 보조기술 동작은 위 배포 후 절차로 확인합니다.
